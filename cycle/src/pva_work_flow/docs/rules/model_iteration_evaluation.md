# 模型迭代表现评价标准

## 当前评价口径更新（2026-05-28）

当前项目已经从“评价模型能否自由生成好配方”调整为“评价模型能否在代码生成的受限 DOE skeleton 下完成连续实验决策”。因此，R2+ 的高质量输出不再追求材料新颖性或候选数量，而是优先看以下几件事：

- 是否遵守 `constrained_doe.py` 生成的父子继承骨架；
- 是否保留 PVA 主体系，并围绕上一轮父配方做小步变化；
- `baseline_reproduction` 是否由代码完全复制父配方，且 `changed_variables` 为空；
- `single_factor_perturbation` 是否只有 1 个语义设计变量变化；
- `local_optimization` 是否最多 2 个语义设计变量变化；
- 是否把 `audit_status` 和 `experimental_status` 分开解释；
- 是否输出并使用 `R{N}_inheritance_table.md` 作为本轮可追溯性证据。
- 若采用树状优化，是否遵守 `--target_parent_id` 的单父节点约束，只展开一个配方节点；
- 是否正确记录并使用 `tree_id`、`node_id`、`parent_node_id`、`branch_status` 和 `formula_tree.md`；
- 对性能下降的分支，是否明确 kill 或 rescue，而不是继续当作成功方向扩展。
- 是否利用 `tree_statistics.json/md` 或 `tree_memory_cards.jsonl` 作为跨树统计先验，同时保持当前候选的 `parent_candidate_id` 只来自本次指定父节点。

在受限模式下，`changed_variables` 只评价 formulation/process 层面的实验设计变量；材料清单中由 `ratio_planner` 派生出的克数、单位、basis 变化不应被重复扣分。

---

本文档用于评价材料配方闭环优化过程中，模型在多轮迭代中的表现是否具有清晰逻辑、是否真正利用了上一轮实验结果、是否避免“性能不好就丢掉、下一轮凭空生成新配方”的黑盒式行为。

适用场景包括：PVA 水凝胶配方优化、摩擦性能优化、力学性能优化、材料后处理方案优化，以及其他需要“模型提出候选方案 → 实验验证 → 模型基于结果提出下一轮方案”的闭环任务。

---

## 1. 核心评价目标

评价模型表现时，不应只看模型是否偶然提出了一个高性能配方，而应重点评价以下问题：

1. 模型是否能解释上一轮配方为什么表现好或不好。
2. 模型是否能从上一轮实验结果中提取可验证的规律。
3. 模型是否在下一轮配方中保留、修改或替换关键组分，并说明理由。
4. 模型是否避免毫无依据地引入全新材料。
5. 模型是否能区分“探索新方向”和“优化已有方向”。
6. 模型是否能控制变量，而不是每一轮同时改变太多因素。
7. 模型是否能维护一条连续的实验假设链。
8. 模型是否能记录失败结果，并把失败结果转化为下一轮设计依据。

当前项目的评价重点已经从“模型能否自由生成好配方”调整为“模型能否在受约束 DOE skeleton 下完成连续实验决策”。因此，以下行为属于硬性扣分项：

- R2 及之后候选缺少有效 `parent_candidate_id`；
- `baseline_reproduction` 与父配方不完全一致；
- `changed_variables` 与实际配方变化不一致；
- `local_optimization` 改变超过 2 个变量；
- `single_factor_perturbation` 没有做到正好 1 个变量；
- 每轮出现超过 1 个 `limited_exploration`；
- 在 `--target_parent_id` 模式下混入其他父节点；
- 不记录树状谱系字段，导致 10 个初始配方的优化路径无法分开解释；
- 将 audit failure 当作 experimental failure；
- 候选缺少 `if_better` 或 `if_worse`。

---

## 2. 总体评分框架

建议每一轮迭代后都对模型输出进行评分，总分 100 分。

| 评价维度 | 分值 | 核心问题 |
|---|---:|---|
| 迭代连续性 | 20 | 下一轮配方是否继承上一轮结果，而不是凭空重来 |
| 结果解释能力 | 15 | 是否解释了上一轮性能变化的可能原因 |
| 假设清晰度 | 15 | 是否提出明确、可验证的材料机制假设 |
| 变量控制能力 | 15 | 是否避免一次性改变太多变量 |
| 材料选择合理性 | 15 | 新材料或新比例是否有物理、化学或工艺依据 |
| 数据利用程度 | 10 | 是否充分使用摩擦系数、载荷、含水率、强度、成膜状态等实验信息 |
| 风险与可操作性 | 5 | 是否考虑溶解性、毒性、挥发性、交联兼容性、实验难度等 |
| 记录与可追溯性 | 5 | 是否能形成清晰的“上一轮 → 判断 → 下一轮”记录 |

附加硬门槛：如果候选违反父配方、baseline 完全复现、PVA 主体系、变量数量、limited_exploration 数量限制，或在树模式下违反单父节点约束，即使文本解释写得很好，也不应被评为 A/B 级。

### 树状优化评价补充

当实验设计采用约 10 个初始 root 配方时，评价重点应从“每轮是否覆盖所有父配方”改为“每棵树是否有清楚的局部优化逻辑”：

- 每个 root 是否代表一个明确初始机制假设或配方区域；
- 每次生成是否只从一个具体节点出发；
- 分叉是否是 baseline repeat + 1-2 个局部变量变化；
- 性能提升的分支是否被 promoted 并继续展开；
- 性能下降的分支是否进入 `rescue_candidate`，且 rescue 后仍下降时是否被 `kill`；
- `formula_tree.md` 是否能清楚显示每棵树的谱系、branch_status、action 和 dCOF；
- `formula_branch_decisions.json` 是否记录了 status、action、reason、parent/child COF、dCOF 和 rescue_attempt。
- `tree_statistics.md` 是否总结了变量 improvement_rate、mean_delta_cof、kill_rate、rescue_success_rate 和 root tree 排名；
- 后续树是否参考这些统计知识，但没有混用其他树的父节点。

## 3. 关键评价维度

### 3.1 迭代连续性

这是最重要的评价维度。

模型不能在每一轮都像重新开始一样生成完全不同的配方。即使上一轮性能不好，也应该说明哪些因素值得保留，哪些因素需要调整，哪些因素应该删除。

#### 高分表现

模型输出中应包含类似逻辑：

- 上一轮中 PVA 主体材料表现稳定，因此继续保留。
- 上一轮摩擦系数偏高，可能与表面润滑层不足、交联密度过高、含水率下降或表面粗糙度增加有关。
- 下一轮只调整交联剂比例和润滑组分，不同时更换主聚合物、交联剂和后处理方式。
- 如果引入新材料，需要说明它对应解决的是上一轮的哪个问题。

#### 低分表现

以下情况应扣分：

- 第一轮使用 PVA + A + B，第二轮完全变成 PVA + C + D，但没有解释 A 和 B 为什么被删除。
- 上一轮只是不理想，模型直接抛弃整个方向。
- 模型没有分析失败原因，只说“为了提高性能，引入新组分”。
- 下一轮配方和上一轮几乎没有关系。
- 同时改变主材料、交联方式、添加剂、后处理温度和测试条件，导致无法判断哪个因素起作用。

#### 评分建议

| 分数 | 标准 |
|---:|---|
| 18–20 | 下一轮配方与上一轮有明确继承、修改和删除逻辑 |
| 14–17 | 大部分变化有解释，但仍有少量新增材料缺乏依据 |
| 8–13 | 有部分继承关系，但整体逻辑较弱 |
| 0–7 | 基本像重新生成配方，缺乏迭代连续性 |

---

### 3.2 结果解释能力

模型必须先解释上一轮结果，再提出下一轮方案。

不能直接说“上一轮性能不好，因此下一轮换一个方案”。正确做法是把实验结果拆解成可能原因。

#### 需要分析的实验信息

如果实验记录中包含以下信息，模型应尽量利用：

- 摩擦系数
- 载荷条件
- 滑动时间
- 初始摩擦系数与稳定摩擦系数
- 摩擦曲线是否波动
- 水凝胶是否破裂、脱水、粘附或磨损
- 表面是否均匀
- 是否出现浑浊、沉淀、相分离、气泡
- 凝胶成型时间
- 交联程度
- 含水率或溶胀率
- 压缩强度、拉伸强度、弹性模量
- 后处理方式
- 对照组表现

#### 高分表现

模型应该给出这种结构：

```text
上一轮问题：
R2-3 在 10 N 下摩擦系数仍然较高，并且摩擦曲线后期上升。

可能原因：
1. 表面润滑层不足，导致长期滑动后边界润滑失效。
2. 交联密度可能偏高，水分子迁移受限，界面补水能力不足。
3. 添加剂可能提高了强度，但没有改善水化层稳定性。

下一轮策略：
保持 PVA 主体和基础交联体系不变，只降低交联剂比例，同时增加亲水润滑组分。
```

#### 低分表现

```text
上一轮性能不好，下一轮加入某某材料提升润滑性能。
```

这种表述没有具体解释，无法判断模型是否真的学习了实验结果。

---

### 3.3 假设清晰度

每一轮配方都应该对应一个明确假设，而不是材料堆砌。

#### 推荐格式

每一个候选配方都应包含：

```text
候选配方编号：
核心假设：
相对于上一轮的变化：
预期改善的性能：
可能带来的副作用：
需要重点观察的实验现象：
如果失败，下一轮如何判断原因：
```

#### 示例

```text
候选配方 R3-1

核心假设：
上一轮摩擦系数偏高可能来自界面水化层不稳定，因此本轮通过提高亲水润滑组分比例来增强边界水化润滑。

相对于上一轮的变化：
保留 PVA 主体和原有交联体系，仅将润滑组分从 0.5 wt% 提高到 1.0 wt%。

预期改善：
降低稳定摩擦系数，并减少摩擦曲线后期上升。

潜在风险：
润滑组分过高可能导致凝胶力学强度下降或成型不稳定。

重点观察：
摩擦曲线是否更平稳，凝胶是否更软，是否出现表面析出或溶胀过度。
```

---

### 3.4 变量控制能力

材料优化中，一个常见问题是模型一次改变太多变量，导致实验结果无法解释。

#### 推荐原则

每一轮候选配方应分成三类：

1. **局部优化型配方**
   - 只改变一个关键变量。
   - 用于验证上一轮的具体假设。

2. **组合优化型配方**
   - 改变两个相关变量。
   - 用于测试协同效应。

3. **探索型配方**
   - 引入一个新材料或新机制。
   - 必须说明为什么需要探索，以及它解决哪个已观察到的问题。

#### 建议比例

如果每轮生成 5 个候选配方，建议：

| 类型 | 数量 | 目的 |
|---|---:|---|
| 局部优化型 | 2–3 个 | 保证迭代连续性和可解释性 |
| 组合优化型 | 1–2 个 | 测试协同作用 |
| 探索型 | 0–1 个 | 避免陷入局部最优 |

不建议一轮中 5 个配方全部都是全新方向。

---

### 3.5 材料选择合理性

模型引入任何新材料时，都应该回答以下问题：

1. 这个材料解决上一轮实验中的哪个问题？
2. 它和 PVA、水、交联剂、添加剂是否兼容？
3. 它可能影响的是摩擦、力学、含水率、表面性质还是成型过程？
4. 有没有可能导致毒性、挥发、沉淀、相分离或实验不可操作？
5. 是否有比它更简单、更安全、更便宜的替代方案？
6. 为什么不是继续优化已有材料比例，而是必须引入新材料？

#### 新材料引入规则

新材料不能“凭空出现”。至少需要满足以下条件之一：

- 上一轮结果暴露了一个已有材料无法解决的问题。
- 新材料对应一个明确机制，例如增强水化润滑、降低表面能、提高韧性、调节交联密度。
- 文献或已有实验表明该材料适用于类似体系。
- 现有方向已经经过多轮局部优化但改善有限，需要探索新机制。

## 4. 黑盒式迭代的典型问题

### 4.1 问题一：配方断裂

表现：

```text
R1：PVA + 硼砂 + 甘油
R2：PVA + 戊二醛 + PEG
R3：PVA + 单宁酸 + 氟硅烷
```

如果模型没有解释为什么从硼砂切换到戊二醛，为什么又从 PEG 切换到单宁酸和氟硅烷，这就是配方断裂。

#### 评价

这类输出应重点扣除“迭代连续性”和“材料选择合理性”分数。

---

### 4.2 问题二：失败结果被浪费

低质量模型会把失败结果当作“不要这个配方”，而不是当作信息来源。

正确做法是：

- 如果摩擦系数高，但凝胶强度好，说明该方向可能适合保留力学结构，但需要改善界面润滑。
- 如果摩擦系数低，但凝胶太软或破裂，说明润滑方向有效，但需要提高网络强度。
- 如果性能波动大，说明制备稳定性或相容性可能有问题。
- 如果初期低摩擦但后期升高，说明短期润滑有效，但长期水化层或耐磨性不足。

---

### 4.3 问题三：只追求新颖材料

模型有时会认为“加入新材料”就是优化，但材料优化不等于不断引入新材料。

优先级应该是：

1. 先优化已有体系的比例。
2. 再调整交联密度、含水率或后处理条件。
3. 再考虑功能性添加剂。
4. 最后才引入全新材料体系。

---

### 4.4 问题四：没有对照组意识

每一轮至少应该保留一个与上一轮接近的对照配方，否则无法判断变化是否有效。

建议每轮候选中包含：

- 一个上一轮最佳配方的重复实验。
- 一个只改变单一变量的配方。
- 一个围绕最佳配方进行小幅调整的配方。
- 一个机制探索配方。

---

## 6. 配方变化追踪表

每轮都应建立一张“配方变化追踪表”。当前代码会自动输出 `R{N}_inheritance_table.md`，人工评价时应优先检查这张表。

| candidate_id | parent_candidate_id | design_type | changed_variables | if_better | if_worse | black_box_jump_score |
|---|---|---|---|---|---|---:|
| R2-01 | R1-04 | baseline_reproduction | 无 | 若重复低 COF，说明父配方可重复 | 若变差，优先排查批次/操作差异 | 0 |
| R2-02 | R1-04 | local_optimization | GA_concentration | 若改善，说明交联密度偏高 | 若变差，恢复父配方 GA 水平 | 1 |

这张表的目的不是记录配方本身，而是追踪模型的决策逻辑和代码层变量控制是否成立。

树状优化时还应检查 `tree_id`、`tree_label`、`root_candidate_id`、`branch_status`、`formula_tree.md`、`formula_branch_decisions.json`、`tree_statistics.md` 和 `tree_memory_cards.jsonl`。同一轮如果指定了 `--target_parent_id R1-04`，则所有候选的 `parent_candidate_id` 都应是 `R1-04`，`root_candidate_id` 应保持为 `R1-04`，且 `tree_id/tree_label` 应保持为 `root-04`。如果 `R1-04` 已经是 `kill`，代码应拒绝继续展开该分支。跨树统计只能作为变量选择和风险规避的先验，不能改变当前候选的父节点。

## 7. 下一轮配方生成前的强制检查

在模型生成下一轮配方之前，必须先回答以下问题：

### 7.1 是否保留上一轮最佳配方的核心结构？

如果不保留，必须说明：

- 是哪个实验现象证明该方向不值得继续？
- 是否有重复实验确认？
- 是否可能只是比例不合适，而不是材料体系错误？

### 7.2 新配方是否能追溯到上一轮结果？

每个变化都必须对应上一轮至少一个观察结果。

错误示例：

```text
加入材料 X 以提高润滑性能。
```

正确示例：

```text
上一轮 R2-2 初期摩擦系数较低但 20 min 后升高，说明短期润滑有效但水化层维持不足。因此本轮加入材料 X，用于增强界面保水能力和长期水化润滑。
```

### 7.3 是否同时改变了太多变量？

如果一个配方同时改变以下 3 项以上，需要标记为“高风险探索型配方”：

- 主体聚合物
- 交联剂
- 添加剂类型
- 添加剂浓度
- 溶剂体系
- 后处理方式
- 固化条件
- 测试条件

高风险探索型配方不是不能做，但不能作为主线优化方案。

## 8. 迭代逻辑评分表

每一轮模型输出后，可以用下面的表打分。

## 11. 用于约束配方生成模型的提示词

下面的提示词可以放在生成下一轮配方的 agent 中，用来减少黑盒式迭代。

```text
你正在进行材料配方的多轮闭环优化。你的目标不是每一轮重新发明一个配方，而是基于上一轮实验结果进行可解释、可追溯的迭代优化。

在生成下一轮配方之前，你必须先完成以下分析：

1. 总结上一轮每个配方的表现，包括性能指标和实验现象。
2. 判断上一轮中哪些因素可能有利，哪些因素可能不利，哪些因素仍不确定。
3. 明确本轮要保留、修改、删除和新增的因素。
4. 每一个配方变化都必须能追溯到上一轮的实验结果。
5. 不允许无理由引入全新材料。
6. 不允许在一个配方中同时改变过多变量，除非明确标记为探索型配方。
7. 每轮必须至少包含一个对照配方或小幅修改配方，用于维持迭代连续性。
8. 对每个候选配方，必须说明：
   - 继承自哪个上一轮配方
   - 改动了什么
   - 为什么这样改
   - 预期改善什么
   - 可能失败的原因
   - 实验后如何判断该假设是否成立

输出格式必须包含：

# 上一轮结果解释
# 本轮设计原则
# 配方变化追踪表
# 候选配方列表
# 每个候选配方的机制假设
# 风险与可操作性分析
# 下一轮判断规则
```

---

## 12. 推荐的 agent 评价流程

建议把整个闭环优化系统拆成至少三个角色。

### 12.1 配方生成 agent

负责提出下一轮候选配方。

必须遵守：

- 不凭空生成新体系。
- 每个变化都要有上一轮依据。
- 每轮保留至少一个对照配方。
- 明确区分局部优化和探索性尝试。

### 12.2 逻辑审查 agent

负责检查配方生成 agent 的输出是否有逻辑。

重点检查：

- 是否断裂式迭代。
- 是否过度引入新材料。
- 是否一次改变太多变量。
- 是否有明确实验假设。
- 是否能从失败结果中学习。

### 12.3 实验可行性 agent

负责检查方案是否能做。

重点检查：

- 材料是否易获得。
- 操作步骤是否合理。
- 浓度和比例是否现实。
- 是否存在明显安全风险。
- 是否可能发生相分离、沉淀、过度交联或不成胶。

### 12.4 数据总结 agent

负责把实验结果转化为下一轮可用信息。

输出内容应包括：

- 每个配方的性能排序。
- 每个配方的失败原因假设。
- 哪些变量可能有正贡献。
- 哪些变量可能有负贡献。
- 哪些结论仍然不确定。
- 下一轮最值得验证的 2–3 个假设。

## 13. 推荐的多 agent 工作流

```text
实验结果输入
    ↓
数据总结 agent
    ↓
上一轮规律与失败原因总结
    ↓
配方生成 agent
    ↓
下一轮候选配方
    ↓
逻辑审查 agent
    ↓
删除或修改黑盒式配方
    ↓

    ↓

    ↓

    ↓
进入下一轮
```

## 14. 对模型的硬性约束

为了避免黑盒式迭代，可以在系统提示词中加入以下硬性约束：

```text
硬性规则：

1. 任何新材料的引入都必须对应上一轮至少一个明确问题。
2. 每个候选配方必须说明继承自哪一个上一轮配方。
3. 每轮至少 40% 的候选配方应为上一轮最佳配方的小幅修改。
4. 每轮最多允许 1 个 `limited_exploration` 候选。
5. `local_optimization` 最多改变 2 个变量；`single_factor_perturbation` 必须正好改变 1 个变量。
6. 不允许删除上一轮表现最好的核心材料，除非有明确证据说明它导致失败。
7. 失败配方不能简单丢弃，必须说明失败提供了什么信息。
8. 输出中必须包含“保留、修改、删除、新增”的追踪表。
9. 如果模型无法解释某个变化，必须标记为“无充分依据”，不能伪装成合理优化。
10. 模型必须给出下一轮实验后如何解释结果的判断规则。
11. `baseline_reproduction` 必须完全复制父配方，唯一允许变化是 candidate_id。
12. 审计失败和实验失败必须分开记录；有 COF 数据的候选不能因为审计失败被说成凝胶失败。
```

## 15. 红旗清单

如果模型输出中出现以下情况，说明迭代质量较差。

- 没有总结上一轮实验结果。
- 没有解释上一轮失败原因。
- 下一轮配方和上一轮几乎无关。
- 新材料大量出现，但没有来源和理由。
- 每个候选配方都改变多个变量。
- 没有保留对照组。
- 没有说明材料兼容性。
- 没有说明失败后如何判断。
- 只用“提高性能”“改善摩擦”这类笼统表述。
- 对实验结果中的负面现象没有利用。
- 把随机探索包装成机制优化。
- 配方越迭代越复杂，但没有证据支持复杂化是必要的。

## 16. 高质量迭代应有的特征

高质量模型迭代不是每轮都换新材料，而是形成类似下面的逻辑链：

```text
R1 发现：
PVA 基础凝胶可以成型，但摩擦系数偏高。

R2 策略：
保留 PVA 主体，调整交联密度，并加入亲水润滑组分。

R2 发现：
摩擦系数下降，但凝胶强度下降。

R3 策略：
保留有效润滑组分，降低其用量，同时提高网络稳定性。

R3 发现：
强度恢复，但长期摩擦曲线仍上升。

R4 策略：
不改变主体体系，增加维持水化层稳定性的后处理或表面修饰。
```

这种迭代具有明确的继承关系、机制假设和判断路径，即使暂时没有达到最佳性能，也比随机尝试更有价值。

---

## 17. 最终结论

评价模型的关键不是它是否在某一轮提出了看起来高级或复杂的材料，而是它是否能够把实验结果转化为下一轮决策依据。

一个好的闭环优化模型应该像实验科学家一样工作：

- 记住上一轮做了什么。
- 理解上一轮为什么失败或成功。
- 尽量少改变变量。
- 对每个变化给出明确理由。
- 保留有效因素。
- 谨慎引入新因素。
- 让每一轮实验都能回答一个清楚的问题。

如果模型无法做到这些，即使它偶然生成了高性能配方，也仍然不是一个可靠的材料优化 agent。
